# TOR13 Website

A static, German-language Jekyll site for GitHub Pages. The published page is HTML and CSS only: events are inserted at build time from `_data/events.json`, and no browser-side JavaScript is used.

## Event updates

A GitHub Actions workflow runs the Python standard-library scraper daily at 04:17 UTC and can also be started manually from the **Actions** tab. It:

1. Fetches the TOR13 event listing from QRTicket.
2. Rejects an unexpected or incomplete page so a source-site change cannot erase good data.
3. Drops events whose start time has passed in `Europe/Berlin` and sorts the remaining events from soonest to latest.
4. Copies event posters into `assets/events/`, removes posters for events no longer listed, and writes `_data/events.json`.
5. Commits only when the event data or poster files changed, then builds and deploys the current site.

Expired events therefore disappear from the site on the next successful scheduled run. GitHub may delay scheduled workflows; the schedule is not an exact-time guarantee.

## Local checks

Python 3.10 or newer is sufficient; there are no Python package dependencies.

```sh
python -m unittest discover -s tests -v
python scripts/scrape_events.py
```

The scraper makes live requests to QRTicket and mirrors its posters when run manually. The tests use a small in-memory HTML fixture and do not require network access.

## GitHub Pages setup

1. Push the repository to GitHub on the `main` branch.
2. In **Settings → Pages**, choose **GitHub Actions** as the build and deployment source.
3. Run **Update events and publish site** manually once to populate the event data and poster assets, or let the next scheduled run do it.

The Jekyll configuration targets `https://tor-13.github.io/website/`. If you attach a custom domain or change the repository name, update `url` and `baseurl` in `_config.yml` to match.

The workflow needs the repository’s default `GITHUB_TOKEN` to have permission to write contents and deploy Pages. If `main` is protected from GitHub Actions pushes, allow the workflow to push its event-data commit or adjust the protection rule.

## Editing

- Main page and semantic markup: `index.html`
- Responsive, nested CSS: `assets/css/site.css`
- Jekyll event data: `_data/events.json` (generated by the scraper)
- Scraper and tests: `scripts/scrape_events.py`, `tests/test_scrape_events.py`
- Locally hosted logo, fonts, gallery, rental PDF, and event posters: `assets/`
